# Content and example language

Documentation prose should remain generic, professional, and reusable. Concrete examples use the fictional autonomous robot café world.

## Tone

Aim for roughly **90% useful, 10% dry/playful**.

Good examples:

- Matcha output · +90% this week
- Robot 04 has discovered enthusiasm.
- Statistically drinkable.
- Foambot 03 denies everything.

Avoid:

- Cutesy robot language
- Emojis as personality
- Meme language
- Excessive jokes inside critical workflows

## Canonical recurring entities

- Matcha Unit 04 / M-04
- Brewbot 07 / B-07
- Tea Unit 02 / T-02
- Foambot 03 / F-03
- Roastbot 11 / R-11 when useful

## Canonical statuses

Ready, Brewing, Working, Queued, Waiting, Calibrating, Complete, Paused, Needs attention.

## Casing

User-facing product and documentation copy MUST use sentence case. Acronyms and proper nouns remain correctly capitalized.
