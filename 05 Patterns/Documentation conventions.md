# Documentation conventions

Matcha Man component pages should teach through **real connected component instances**, not text-only descriptions or hand-drawn proxies.

## Page structure

Source/master component sets and compact QA can remain on the right. Documentation sections on the left SHOULD include connected examples.

Typical sections:

- Overview
- Anatomy
- Variants
- States
- Content
- Behavior
- Accessibility
- Examples

Customize the structure to the component rather than forcing identical sections everywhere.

## QA

Prefer curated QA over exhaustive Cartesian matrices. Test representative combinations, long content, theme, and responsive behavior.

## Casing

Documentation uses sentence case.

## Example content

Documentation prose remains generic; robot-café content demonstrates usage.
